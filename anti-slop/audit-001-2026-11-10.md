RasaKarya Anti-Slop Audit 001
Date: 2026-11-10
Mode: AFTER
Scope: pages/, css/, js/
Design Read: Existing DESIGN.md defines a warm artisan bakery identity using Plus Jakarta Sans, Playfair Display, Manrope, cream, brown, orange, and gold. The requested navbar is centered. Current audit only; no UI changes are applied by this audit.

Findings

1. HIGH, R-35 / R-26: Forms need a recorded submit behavior and feedback path.
   Evidence: pages/partnership.html, pages/product.html, and pages/service-order.html contain forms; js/script.js only handles cart buttons and the mobile menu. No submit listener or form action is present.

2. HIGH, R-27: Data-driven UI states are incomplete.
   Evidence: product/cart interactions have no explicit loading, empty, or error presentation. Forms also have no visible success or error state beyond native required validation where present.

3. HIGH, R-32: Keyboard focus styling is not explicitly defined.
   Evidence: css/ contains no visible :focus or :focus-visible rule. Browser default focus may vary and is not a deliberate design treatment.

4. HIGH, R-35 / R-03: Full click-through and responsive verification is still outstanding.
   Evidence: static source inspection found the interactive surface, but no browser run, console check, mobile overflow check, or element-by-element click-through has been recorded in the project.

5. MEDIUM, R-01 / R-12: The global stylesheet uses a radial gradient in the hero and multiple shadows without documenting their purpose in source.
   Evidence: css/style.css uses radial-gradient in .hero and box-shadow in .primary, .hero-visual aside, and other surfaces. Keep only where it supports the hero focal point or elevation hierarchy, and document the reason.

6. MEDIUM, R-09 / R-04: Decorative presentation patterns need a content-purpose pass.
   Evidence: collection and product pages use uppercase labels and emoji cart text in some pages. Replace decorative emoji with the existing relevant cart icon treatment, and retain uppercase labels only where they classify the product or section.

7. LOW, R-14 / R-05: Several collection and service sections use repeated equal-weight cards.
   Evidence: css/collections.css and css/service-order.css use uniform card grids. The content hierarchy would read more clearly with one primary card or a list treatment where the items are supporting choices.

8. LOW, R-16 / R-38: Claims and numbers need source confirmation before being presented as factual.
   Evidence: pages/home.html and pages/partnership.html contain values such as 24+, 7 hari, 15.000+, 35+, 100%, 4.9/5, and certification wording. They should stay only if the project owner confirms their source; otherwise label them as placeholders or remove them.
